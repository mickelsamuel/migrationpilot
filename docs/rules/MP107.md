# MP107: warn-citus-distributed-ddl

**Severity**: Warning | **Auto-fixable**: No | **Tier**: Free (needs `--database-url`)

## What It Detects
`ALTER TABLE` against a table that Citus's catalog says is distributed.

## Why It's Dangerous
A distributed table is a set of shards spread across worker nodes. Citus propagates DDL to all of them, so one line in the migration becomes a lock on the coordinator plus a lock per shard across the cluster, and the statement is not finished until the slowest worker is finished. Anything blocking on the coordinator blocks the whole cluster for that table.

Some forms are not propagated at all — they are refused. Changing the distribution column is the one people hit: Citus answers "cannot execute ALTER TABLE command involving partition column" and the migration stops there. MP107 says so explicitly when it can see that the ALTER targets the distribution column.

## Requires Production Context
Whether a table is distributed, what it is distributed by, and how many shards it has all come from Citus's metadata — the `citus_tables` view, falling back to `pg_dist_partition` and `pg_dist_shard` on older versions. There is no way to know any of it from the migration file, so without `--database-url` the rule stays silent.

Reference tables are deliberately not flagged. They are replicated rather than sharded, and the cost profile is different enough that lumping them in would be misleading.

## Bad Example
```sql
-- orders is distributed by tenant_id across 32 shards
ALTER TABLE orders ALTER COLUMN tenant_id TYPE bigint;
-- ERROR: cannot execute ALTER TABLE command involving partition column
```

## Good Example
```sql
-- See what the statement fans out to:
SELECT table_name, citus_table_type, distribution_column, shard_count
FROM citus_tables;

-- For an ALTER Citus will propagate, serialise it if parallel propagation is
-- deadlocking against other work, and fail fast rather than stalling:
BEGIN;
SET LOCAL citus.multi_shard_modify_mode TO 'sequential';
SET LOCAL lock_timeout = '5s';
ALTER TABLE orders ADD COLUMN note text;
COMMIT;
```

Changing the distribution column is not an ALTER at all — it means redistributing the table, with `undistribute_table` plus `create_distributed_table`, or `alter_distributed_table`. Either way it moves data and belongs in its own maintenance window.

## Auto-fix
This rule is not auto-fixable. Redistributing a table is a data-movement operation, not a rewrite of the statement.

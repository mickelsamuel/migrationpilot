# MP111: warn-timescale-columnstore-ddl

**Severity**: Critical | **Auto-fixable**: No | **Tier**: Free (needs `--database-url`)

## What It Detects
An `ALTER TABLE` form that TimescaleDB refuses on a hypertable with compression (columnstore) enabled: `ALTER COLUMN ... TYPE`, `ALTER COLUMN ... SET STORAGE`, and the row-level security commands.

## Why It's Dangerous
This is not a slow path — the statement fails. TimescaleDB answers with "operation not supported on hypertables that have columnstore enabled", and the migration stops there, partway through, with whatever ran before it already applied.

Getting the change through is a procedure rather than a fix: stop the columnstore policy, convert the compressed chunks back to rowstore, disable the columnstore, apply the change, then re-enable the columnstore and restore the policy. Two of those steps move all of the hypertable's data. That belongs in its own maintenance window, not inside a migration run.

MP111 is critical rather than a warning because the outcome is known: this statement will error.

## Requires Production Context
Compression state comes from `compression_enabled` in `timescaledb_information.hypertables`. Without `--database-url` MigrationPilot has no way to know whether the hypertable's chunks are compressed, so the rule stays silent — and the same ALTER against an uncompressed hypertable is perfectly legal, so guessing would be wrong.

## Bad Example
```sql
-- metrics is a hypertable with the columnstore enabled
ALTER TABLE metrics ALTER COLUMN value TYPE numeric;
-- ERROR: operation not supported on hypertables that have columnstore enabled
```

## Good Example
```sql
-- Confirm the columnstore state first:
SELECT hypertable_name, compression_enabled, num_chunks
FROM timescaledb_information.hypertables
WHERE hypertable_name = 'metrics';
```

Then run the change as its own operation:

1. remove the columnstore policy for `metrics`
2. convert the compressed chunks back to rowstore
3. disable the columnstore on the hypertable
4. `ALTER TABLE metrics ALTER COLUMN value TYPE numeric;`
5. re-enable the columnstore and restore the policy

Steps 2 and 5 rewrite every chunk, so size the window for the whole hypertable, not for the ALTER.

## Auto-fix
This rule is not auto-fixable. The workaround moves data across every chunk, which is not something to do implicitly.

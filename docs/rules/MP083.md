# MP083: warn-fk-nondeterministic-collation

**Severity**: Warning | **Auto-fixable**: No | **Tier**: Free

## What It Detects
A foreign key created in a migration that also uses a non-deterministic collation (ICU collations such as `und-x-icu`). Only fires when the target version is PG18+.

## Why It's Dangerous
A non-deterministic collation treats distinct byte sequences as equal — that is the point of a case-insensitive or accent-insensitive collation. Applied to a foreign key column, it means `"abc"` can satisfy a reference to `"ABC"`, so the key you thought was pointing at one row may match several, and which one you get is not something you control. PostgreSQL 18 stopped allowing this: it validates that foreign key columns use deterministic collations and rejects the constraint outright at creation time. A migration that worked on PG17 will fail on PG18, and the failure arrives mid-deploy rather than in review.

## Bad Example
```sql
CREATE TABLE orders (
  code TEXT COLLATE "und-x-icu",
  FOREIGN KEY (code) REFERENCES products(code)
);
-- PG18 rejects this FK outright
-- On earlier versions, "abc" could match "ABC"
```

## Good Example
```sql
CREATE TABLE orders (
  code TEXT COLLATE "C",
  FOREIGN KEY (code) REFERENCES products(code)
);
```

## Auto-fix
This rule is not auto-fixable. Changing a column's collation rewrites the table and affects every comparison and index on that column, so it needs a deliberate migration. Check the current collation first:

```sql
SELECT collation_name FROM information_schema.columns
WHERE table_name = 'orders' AND column_name = 'code';
```

Then move the column to a deterministic collation before adding the foreign key. If you need case-insensitive matching elsewhere, apply the ICU collation per-query or to a separate column rather than to the key itself.

## Configuration
```yaml
rules:
  MP083: false           # disable
  MP083:
    severity: critical   # upgrade from warning to critical
```

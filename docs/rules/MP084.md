# MP084: require-default-for-not-null-column

**Severity**: Critical | **Auto-fixable**: No | **Tier**: Free

## What It Detects
`ALTER TABLE ... ADD COLUMN ... NOT NULL` with no `DEFAULT`. Columns that populate themselves are not flagged: `DEFAULT`, `GENERATED ALWAYS AS IDENTITY`, `GENERATED ALWAYS AS (expr) STORED`, and the `SERIAL` pseudo-types all give existing rows a value.

## Why It's Dangerous
PostgreSQL has to put something in the new column for every row that already exists. Without a `DEFAULT` there is nothing to put there, so the statement fails:

```
ERROR: column "email" of relation "users" contains null values
```

The whole migration rolls back with it. What makes this one worth catching in review is where it fails. An empty database accepts the identical statement without complaint, so the migration passes locally, passes in CI, passes in any environment seeded from scratch — and then aborts in staging or production, which are the only places with rows in the table. The failure lands mid-deploy, and if the migration runner has already applied earlier statements in separate transactions, you are left partway through.

## Bad Example
```sql
ALTER TABLE users ADD COLUMN email TEXT NOT NULL;
-- Fine on an empty table, fatal on a populated one
```

## Good Example
```sql
-- If there is a sensible default, use it. On PG 11+ a constant default
-- is a catalog-only change — no table rewrite.
ALTER TABLE users ADD COLUMN email TEXT NOT NULL DEFAULT '';
```

```sql
-- If there is no sensible default, add the column nullable, backfill it,
-- and tighten afterwards without a long lock.
ALTER TABLE users ADD COLUMN email TEXT;
-- backfill in batches...
ALTER TABLE users ADD CONSTRAINT users_email_not_null
  CHECK (email IS NOT NULL) NOT VALID;
ALTER TABLE users VALIDATE CONSTRAINT users_email_not_null;
```

## Auto-fix
This rule is not auto-fixable. Choosing the value existing rows should get is a decision about your data, and picking one automatically would be a guess. If you can name a default, adding it is a one-word change; if you cannot, the column should not be `NOT NULL` yet.
